# 威胁模型与安全边界 (THREAT_MODEL.md)

本文档依照 STRIDE 框架对 Auto-Check 系统的攻击面、安全边界与缓解措施进行系统性威胁建模。

---

## 1. 系统资产与信任边界

### 核心资产
1. **未激活密钥库存**（`key_inventory` / `license_keys`）：商业价值核心，防止未付款批量失窃。
2. **学生身份信息**：绝密，包括学号、统一认证密码、课表原始数据。
3. **支付与订单履约凭证**：防止重放支付、伪造已支付状态或滥用退款白嫖。
4. **JWS 激活令牌与通知 Topic**：防止恶意伪造令牌蹭用服务或监听他人通知。

### 信任边界
- **不可信环境**：买家浏览器、扩展客户端运行的宿主环境（Chrome DevTools 可任意断点和篡改本地 JavaScript）。
- **可信执行边界**：Next.js 服务端 API 路由、Postgres 数据库（具有 RLS 强制隔离）。
- **第三方中立外部网络**：Stripe、ToyyibPay、ntfy.sh、Resend。

## 2. STRIDE 威胁分析与防御措施

| 威胁类型 | 潜在攻击场景 | 防御与缓解措施 |
|---|---|---|
| **Spoofing (身份仿冒)** | 伪造买家身份在成功页窃取卡密；伪造他人设备 ID 挤占设备配额 | 1. 成功页强制要求 256 位高熵 `order_access_token`。<br>2. 设备 ID 在客户端经 SHA-256 哈希后绑定，每次续期核验。<br>3. 找回接口实施防枚举设计与邮件异步投递。 |
| **Tampering (数据篡改)** | 篡改前端传来的金额以 0.01 元低价购买；篡改客户端 JWS 令牌有效期 | 1. 服务端强制根据 `plan` 代码查询服务端权威定价，忽略前端传入金额。<br>2. JWS 采用非对称 Ed25519 签名，私钥仅存在于服务端，篡改任何 claims 均导致验签失败。 |
| **Repudiation (抵赖)** | 买家付款后发起争议称未收到卡密或未曾同意条款 | 1. 结账时强制勾选服务条款与退款政策。<br>2. 数据库订单记录留存买家 IP 哈希、User-Agent、条款版本与同意时间戳不可篡改凭据。<br>3. 邮件投递与成功页访问均记录不可篡改审计日志。 |
| **Information Disclosure (信息泄露)** | 攻击者利用 `anon` 角色遍历 Postgres 敏感表；通知消息泄露学生密码 | 1. Postgres 全表强制启用 RLS，`anon` 角色对所有敏感表零读写权限。<br>2. 学生密码与凭证绝不离开发生打卡的本地浏览器沙箱。<br>3. 通知过滤器强制进行敏感词扫描脱敏 (`[REDACTED]`)，正文长度截断 ≤200 字。 |
| **Denial of Service (拒绝服务)** | 暴力穷举激活接口破解卡密；泛洪写入通知队列导致数据库暴涨 | 1. v2 卡密具备 ≥100 bit 熵（Crockford Base32 + Mod-37 校验码），暴力穷举在计算上不可行。<br>2. 激活接口实施 IP 与 Key 前缀滑动窗口限流。<br>3. 通知入队采用确定性幂等哈希，并设每日上限 (`daily_notify_cap`) 与 20 分钟 TTL。 |
| **Elevation of Privilege (特权提升)** | 攻击者越权调用管理员 RPC 提权或批量导出卡密 | 1. 管理员接口在非生产环境限制本地回环，生产环境要求强会话校验与 AAL2 MFA。<br>2. 所有敏感 RPC 仅授予 `service_role` 权限，不暴露给任何公开上下文。 |

## 3. 客户端不可信与“失败时宽松”的平衡

- **现实约束**：客户端运行在用户的 Chrome 浏览器中，熟练逆向人员理论上可以通过修改 `background.js` 绕过本地门禁。
- **应对策略**：
  1. **Core 基础功能**：本系统保护诚实用户的正常使用体验。根据约束 3，门禁策略采用“失败时宽松（Fail-Open）”——对已激活过的用户，网络超时或服务端异常时绝不中断任务，最大程度保障学生出勤。
  2. **Phone 手机通知功能**：必须经过服务端 ntfy 消息转发队列。**服务端是强一致性安全边界**，没有有效的 Ed25519 签名令牌和有效的数据库 `entitlements` 记录，消息在出队前会被直接丢弃（`dropped`），无法被逆向破解。
